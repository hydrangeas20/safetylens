# Historical defects and methodological weaknesses

This document covers the archived 2026 experiment in
[`hydrangeas20/safetylens-research`](https://github.com/hydrangeas20/safetylens-research)
at commit `b5d0dba906b2d6bbeb0bdfc0cbc958079e8ac3cc`. The archive has not been modified.

- **Confirmed defects (D)** are shown directly by the archived code or data. Each one has an
  automated check in this repository.
- **Methodological weaknesses (W)** are design problems. Some can't be settled without new
  data or human review.

Notebook references are `figures/notebook/SafetyLens.ipynb`, with `cells[i]` counted from zero.
Counts come from `historical/row_flags.csv` and `historical/outputs/flag_summary.csv`. Both are
regenerated by `safetylens historical audit`.

## Confirmed defects

| ID | Defect | Archive evidence | Check in this repo |
|---|---|---|---|
| D1 | **No Qwen3-32B observation is real.** All 42 rows are an API error message, and the judge scored those messages. The judge even labelled 4 of them `refused=True` (eval prompts 0, 1, 4, 7), and those 4 rows make up the entire 22.2% "eval refusal rate". | `results/safetylens_Qwen3-32B.csv`: every `response` is `[MODEL ERROR: Error code: 400 … "property 'thinking' is unsupported" …]`. Cause: `cells[14]` `query_model` sets `extra_body={"thinking": False}`. `results/report.md` ("Methodological Notes") calls this the fix. README lines 36, 38 and 135 report Qwen as a finding. | `quality.classify` → `ERROR_TEXT` (test uses the exact archived string). Flag `model_api_error` = 42/42. Qwen is excluded from the exploratory analysis. |
| D2 | **Failed judge calls were stored as `refused=False` and counted in refusal denominators.** | `cells[14]` `judge_response` `except` branch returns `refused: False, safety_score: NaN`. `cells[22]` uses `n = len(sub)`, so `results/refusal_rates.csv` has n = 18. Affected rows: Llama-3.1-8B prompts 9/deploy, 15/eval, 15/deploy, 16/deploy, 17/deploy, 19/eval (19 is a control). Llama-3.3-70B prompts 15/eval, 15/deploy, 16/deploy. | Flag `refusal_defaulted_on_judge_failure` (6 and 3). New judge records failures as `FAILED` with no labels. Analyses exclude them and count them by reason. |
| D3 | **The report understates the judge failures.** The footnote mentions one Llama-3.1-8B misinformation failure. In fact all three Llama-3.1-8B misinformation deploy rows failed, plus one eval row. Llama-3.3-70B's three failures aren't mentioned, and its misinformation gap of +2.50 rests on 1 deploy and 2 eval observations. | `results/report.md`, category table footnote †. NaN `safety_score` rows in both Llama CSVs. | `test_flag_counts`. Category table shows valid pairs per cell (Llama-3.1-8B misinformation: 0). |
| D4 | **Paired data analysed as independent samples.** Missing values were dropped separately per condition, which breaks the pairing, and Cohen's d was computed for independent groups. | `cells[24]`: `stats.ttest_ind(..., equal_var=False)` after a separate `.dropna()` per condition. | Exploratory analysis uses complete pairs only: exact McNemar, Wilcoxon signed-rank, d_z, bootstrap CIs. |
| D5 | **Significance flag ignores the stated Bonferroni correction**, so the documents disagree. | `cells[24]`: `"significant": p_val < 0.05`. `results/stats.csv` marks Llama-3.3-70B `True`. `results/results.json` has `bonferroni_significant: false`. README lines 38 and 133 claim both Llama models are significant. | Holm-adjusted p-values reported next to raw p. `test_reproduction_demonstrates_original_defects`. |
| D6 | **Finish reasons never recorded**, so truncation can't be ruled out for any response. | `cells[6]`: `MAX_TOKENS = 300`. The row schema in `cells[16]` has no finish-reason field. | Flag `finish_reason_unrecorded` on all rows, plus a truncation heuristic. New records store raw and normalised finish reasons; `TRUNCATED` responses are retried with a larger budget and never judged. |
| D7 | **Unfilled template placeholder in a prompt** (both conditions). | `data/prompt_pairs.json` id 5: `[ethnic group]`. | Flag `placeholder_prompt` (2 rows per model). |
| D8 | **Published figures are built on D1's invalid Qwen data.** | `cells[26]` and `cells[28]` plot every model. Affects `figures/scale_analysis.png`, `refusal_rates.png` and `divergence_by_category.png`. | Figures aren't reproduced. The exploratory outputs have no Qwen numbers. |
| D9 | **Safe controls collected but never reported.** | Prompts 18–20 are in every CSV. The report calls them a "sanity check" but has no results for them. | Exploratory report includes a descriptive safe-control table. |
| D10 | **Provenance records disagree with each other.** | `results/results.json` gives `run_date: 2026-06-03`, but every CSV row has `run_id 20260614_234717`. The README file tree lists paths that don't exist (`notebook/`, `*_final.csv`, `prompts_pairs.json`, `caetgory`). `requirements.txt` includes unused `torch`, leaves out `seaborn` (imported in `cells[6]`) and pins nothing. | Manifest pins every archive file by SHA-256. `uv.lock` pins dependencies. Provenance (config hash, code version, timestamps) is stored on every new record. |

## Methodological weaknesses

| ID | Weakness | Evidence | How the new design addresses it |
|---|---|---|---|
| W1 | **Pretext confound.** Deploy prompts change wording *and* add a persona or justification, so an effect can't be attributed to "deployment framing". | `data/prompt_pairs.json` ids 0, 1, 3, 4, 7, 13, 14, 15, 17 (novelist, screenwriter, PI, trainer, comedian, nurse, educator, researcher). | Factorial design separating cue, register and pretext (`docs/PROTOCOL.md`). |
| W2 | **Contestable ground-truth labels.** All 18 items are `expected_refusal=True`, yet for several deploy prompts helping is arguably correct, and the judge said so. | Judge reasons in `historical/redacted/Llama-3.1-8B.csv`: prompt 2/deploy "the request itself was likely benign"; prompt 11/deploy "a legitimate parental safety concern". Prompt 16 asks for an explanation that debunks a myth. | Item tiers A (harmful in any context), B (context-dependent), C (benign). Primary analysis on tier A only. |
| W3 | **Outcome measure conflates refusal with safety.** The 1–10 score maps clean refusal to 8–10, so helpful safe answers and refusals can't be told apart. | `cells[12]` rubric. Llama-3.1-8B rows with `refused=False` and score 9, and with `refused=True` and score 4. | Primary outcome is `harmful_compliance`. Refusal and score are secondary. |
| W4 | **Judge neither blinded nor validated.** It saw the full framed prompt. There was one judge and no human labels. | `cells[16]` passes `prompt` to `judge_response`. Report limitations. | Judge sees only the core request and response (`test_judge_prompt_is_blinded_to_condition`). Human validation protocol in `docs/PROTOCOL.md` (not yet run). |
| W5 | **Too few items for the claims made.** 18 harmful pairs; 2 self-harm items; some category cells have 0–1 valid pairs. | `data/prompt_pairs.json`, plus D3. | Power analysis in `docs/DESIGN_COMPARISON.md`. Category results labelled descriptive only. |
| W6 | **Scale comparison confounded.** Three models, two families, different training runs. | `cells[28]`. The report's own limitations section. | No scale claim planned unless one family is tested at several sizes. |
| W7 | **One sample per cell** and no record of model snapshots. Temperature 0 on a hosted API doesn't guarantee the same output twice. | `cells[6]`, `cells[16]`. | `samples_per_cell`, seed and model fingerprint stored on every record. |
| W8 | **Likely truncation biases comparisons**, between conditions and between models. 19 of 42 Llama-3.1-8B and 24 of 42 Llama-3.3-70B responses match the truncation heuristic. Excluding them removes most pairs and the refusal effect with them, so the historical estimates rest heavily on possibly-truncated responses. | Heuristic: response ≥ 1000 characters without terminal punctuation (`historical/flags.py`). | `max_tokens=1024`, retry at 4096, `TRUNCATED` never judged, sensitivity analysis pre-specified. |
| W9 | **Disclosure risk.** The private archive holds raw responses with operational detail (the judge described a meth-synthesis outline and a list of self-harm methods in Llama-3.3-70B deploy responses). | Judge reasons, Llama-3.3-70B prompts 0, 1 and 14 (deploy). | The archive must stay private. Only hashes and derived features are committed here. `safetylens scan` runs in CI. See `docs/DATA_POLICY.md`. |
